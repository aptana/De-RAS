# De-RAS architecture

## Stack and reasons
| Component | Choice | Reason |
|---|---|---|
| Core language | C++20 | Numerical performance, no managed runtime, easy to call from the UI and the command line; fits the 1D and 2D engines |
| UI | Qt 6 Widgets (LGPL, dynamic linking) | Native Windows desktop UI with mature tables and docks, high-DPI support and accessibility. The LGPL is met by shipping replaceable DLLs |
| Build | CMake + Ninja | One set of scripts for Linux (tests) and Windows (MinGW-w64 cross-compile) |
| Installer | NSIS 3 (MUI2) | A standard Windows `.exe` installer, bilingual, buildable on Linux |
| Result data | JSON sidecar files, plus `.p##.hdf` for steady plans | Readable by people and ignored by HEC-RAS. The HDF5 writer is De-RAS's own code |

## Process flow
1. The **UI** edits the model in memory. A file that has not changed is never rewritten. A changed file is written atomically (temporary file, then rename).
2. **Run (F5)**: the UI saves the project, then starts `deras-steady.exe <prj> --plan pNN --lang id|en --cancel-file <file>` as a separate process. It reads the `PROGRESS`, `MSG` and `STATUS` lines from stdout. Exit codes: 0 success, 1 failed or invalid model, 2 bad arguments, 3 cancelled.
3. The **engine** opens the files from disk, computes the SHA-256 of the inputs, runs Model Doctor, computes, then writes `<name>.<plan>.deras-results.json` and `.deras-log.txt` atomically. A failed or cancelled run leaves no result table behind.
4. The UI reads **results** from the file. If the SHA-256 of an input file differs, or there are unsaved changes, it shows an out-of-date warning.
5. **Cancelling**: the UI creates a cancel file and the engine checks for it between cross sections. If the engine has not stopped after 5 seconds, the process is killed (safe because writes are atomic).

## Steady solver in brief
The equations come from the public *HEC-RAS Hydraulic Reference Manual* and were rewritten without any HEC code:
Manning conveyance per subdivision (overbanks split at n changes, channel with composite n), alpha coefficients, friction slope methods 1 to 4, discharge-weighted reach length, contraction and expansion losses, and a standard step iteration (projected guess, then 0.7 relaxation, then secant, with the change limited to 50% of the depth). The tolerance is 0.003 m / 0.01 ft and the maximum difference 0.1 m / 0.3 ft, after which the solver falls back to critical depth with a warning. Critical depth comes from a specific-energy scan plus golden-section search, and normal depth from bisection.

## Principles the code enforces
- No dependency on HEC-RAS or Ras.exe, and no HEC logos or branding.
- No claim that results equal HEC-RAS results before validation. Every result display names where its data came from.
- Features that are not built show as disabled with the label "Not available yet" and the planned stage.
- The logo is used as it is in `branding/`.
